API docs

A JSON API that validates and formats phone numbers offline, using Google's libphonenumber numbering-plan metadata (libphonenumber-js {{metadataVersion}}, "max" set, {{regionCount}} regions). Base URL: https://phonecheck

Numbering-plan check only. No carrier, HLR or live-line lookup. "Valid" means the number matches a range allocated in the metadata. PhoneCheck does not know whether a number is connected, reachable, active, or who holds it, and it does not identify the carrier. Line type reflects the original allocation; ported numbers may differ. Don't use it as your only fraud, KYC or deliverability control.

POST/v1/parse

Send the number as typed: spaces, dashes, dots, brackets, a leading 00/+ and extensions (ext. 89, x89) are understood. Numbers without a +country code need defaultCountry (ISO 3166-1 alpha-2, e.g. GB). Max {{maxNumberLength}} characters; body max {{singleBodyKb}} KB.

curl -X POST https://phonecheck/v1/parse \
  -H "Content-Type: application/json" \
  -d '{"number": "020 7946 0018", "defaultCountry": "GB"}'
{{example:020 7946 0018:GB}}

An invalid number still returns 200, with valid: false, a reason code and a message:

{{exampleshort:+1 555 555 5555:}}

Formats (e164, international, national, rfc3966) are filled in when the number is at least possible (right length); otherwise they are null. line_type is set only for valid numbers, and only when the metadata defines it.

POST/v1/bulk (Pro key)

Normalise a list: up to {{bulkMax}} numbers per request, body max {{bulkBodyKb}} KB. Items are strings, or objects {"number": "...", "defaultCountry": "FR"} to override the request-level defaultCountry. Each number counts as one call toward the monthly quota; the whole request is refused (nothing charged) if it doesn't fit in what's left. Results come back in input order with the same fields as /v1/parse (minus example), plus index.

curl -X POST https://phonecheck/v1/bulk \
  -H "Authorization: Bearer pc_live_..." -H "Content-Type: application/json" \
  -d '{"defaultCountry": "US", "numbers": ["(213) 373-4253", "+44 20 7946 0018", {"number": "01 23 45 67 89", "defaultCountry": "FR"}, "12"]}'

Limitations

  • No carrier, HLR, porting or reachability data. PhoneCheck never contacts a network. It can't tell you whether a number is in service, which carrier serves it now, or whether it can receive SMS.
  • Line type comes from the numbering plan. Mobile numbers ported to fixed or VoIP services (and vice versa) keep their original type. US and Canada numbers are fixed_line_or_mobile because the plan doesn't separate them.
  • Metadata is a snapshot (libphonenumber-js {{metadataVersion}}). New number ranges may show as not_valid_number until the metadata is updated.
  • Short codes, emergency numbers and SMS short numbers are not validated.
  • Bulk max {{bulkMax}} numbers per request (Pro). Chosen so a cold isolate stays under the Worker cpu_ms = 100 cap (a cold 1,000-number bulk once measured ~85 ms). Split larger lists. Atlas can raise cpu_ms if a larger bulk is needed later.
  • GET /v1/parse/{number} is for staging / quick tests only. Production returns 405 and points you to POST /v1/parse so numbers never land in URL paths or proxy logs.

Privacy

  • Numbers you send are processed in memory to build the response and then discarded. PhoneCheck does not store them, log them, or send them anywhere (no third-party lookups, no analytics).
  • Workers observability/logging is turned off for this service. The only data kept is counters: calls per API key per month, and total calls per day.
  • Use POST so numbers stay out of URLs. The web checker on the home page always uses POST.
  • API keys are stored as SHA-256 hashes; no email or personal data is needed for a key.
  • Like any HTTPS service on Cloudflare, Cloudflare processes connection metadata (such as IP address) to deliver and protect the service; per-IP rate limiting uses it transiently.
